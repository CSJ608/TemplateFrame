> English · [中文](README.md)

A "template ⇄ data" contract engine: **export and import are two directions of the same contract**—

- **Export (Fill)** = template + typed data → file
- **Import (Parse)** = file → validated against the contract → typed data

Templates are generated by code; users only restyle them. On upload, the framework validates the template against the contract (what's missing, what's extra, exactly where).

> The Chinese README is the primary, fully maintained document; this English mirror covers the same ground.

## Which package

| Your need | Install | Notes |
|---|---|---|
| **List import / export** (header row + data rows) | `TemplateFrame.Excel.Simple` | A `List<T>` in and out of xlsx — the simplest path |
| **Word documents for printing** (header/footer, tables, images) | `TemplateFrame.Word` | Content-control (SDT) tagging; restyling never breaks read-back |
| **Complex Excel forms** (merged cells, images, free layout) | `TemplateFrame.Excel` | Named-range tagging, grid-style layouts |

All three plugins depend on the base package `TemplateFrame` (contract model + typed service base). Only need a plain Excel table without the contract layer? The static `SimpleExcel.Write / Read` class inside `TemplateFrame.Excel.Simple` works standalone.

## Target frameworks

All four packages multi-target `netstandard2.0 / net462 / net8.0`; NuGet picks the asset automatically:

| Your runtime | Asset |

## Quick start: import & export in 3 minutes

Using a materials list (`TemplateFrame.Excel.Simple`):

```bash
dotnet add package TemplateFrame.Excel.Simple
```

**① Define a scenario service** — declare the contract (which columns); layout and mapping are automatic:

```csharp
using TemplateFrame.Contract;
using TemplateFrame.Excel.Simple;

public sealed class MaterialsService : SimpleExcelTemplateService<MaterialsData>
{
    protected override TemplateContract DefineContract() => new()
    {
        Name = "Materials",
        Version = "1.0",
        Elements =
        [
            new TableElement
            {
                Key = "Materials",
                DataPath = "Items",          // maps to MaterialsData.Items automatically
                Columns =
                [
                    new TextElement { Key = "Code", DisplayName = "Code", DataPath = "Code", Required = true },
                    new TextElement { Key = "Name", DisplayName = "Name", DataPath = "Name", Required = true },
                    new TextElement { Key = "Unit", DisplayName = "Unit", DataPath = "Unit" },
                ],
            },
        ],
    };
}
```

**② Four operations**:

```csharp
var service = new MaterialsService();

using var template = service.BuildTemplate();   // generate the template (header-only xlsx, hand it to users)
using var filled   = service.Fill(data);        // typed data → filled xlsx (export)
var validation    = service.Validate(template); // check an uploaded template against the contract
var parsed        = service.Parse(filled);      // read a file back → typed MaterialsData (import)
```

`TData` can even be a `List<MaterialLine>` directly (root collection — leave the table's `DataPath` empty), no wrapper object needed.

## Core model

- **Contract = element list**: `TemplateContract` declares the elements of a scenario (`TextElement` / `ImageElement` / `TableElement`). Column names, validation rules, and mapping keys all come from this single declaration.
- **Layout belongs to the application**: the contract does not produce layout. Your service composes the layout in `BuildInitialTemplate()` with the plugin's typed builder; or let a designer build the file in Word and let `Validate` check it.
- **`FillData` shape**: a plugin-agnostic weakly-typed container. Declare `DataPath` on contract elements for automatic mapping (the default), or hand-write `MapToData` / `MapFromData` for full control.
- **Tiered validation**: `Validate` fails hard on upload (Missing / WrongType / Ambiguous; missing optional fields only warn). `Fill` validates softly (`Drifted` / `Extra` become warnings and continue; a missing required element throws by default — configurable via `MissingElementPolicy.SkipAndWarn`). Use `FillDetailed` when you need the warning list.

## Word / Excel flexible layouts

For complex documents, inherit `TemplateService<TData, TBuilder>` — declaring the builder type declares the plugin:

```csharp
public sealed class DeliveryOrderService : TemplateService<DeliveryOrderData, WordTemplateBuilder>
{
    public DeliveryOrderService() : base(new WordTemplateEngine()) { }

    protected override TemplateContract DefineContract() => /* element list */;

    protected override void BuildInitialTemplate()
    {
        Builder.SetPageSetup(new PageSetup { Size = PageSize.A5, Orientation = PageOrientation.Landscape });
        Builder.AddHeader(BuildHeader);
        Builder.AddTable("Lines", ["No.", "Material", "Qty"],
            new TableFormat { ColumnWidthsCm = [1.8, 8.5, 3.2] });
        Builder.AddImage("QrCode", widthInches: 1.0, heightInches: 1.0);
    }
}
```

- `WordTemplateBuilder`: `SetPageSetup` / `AddHeader` / `AddFooter` / `AddParagraph` / `AddText` / `AddElement` / `AddTable` / `AddImage` / `AddPageNumber` / …
- `ExcelTemplateBuilder`: `SetSheetName` / `AddText(cell, text)` / `AddElement` / `AddTable` / `AddImage` / `MergeCells` / `SetColumnWidth` / …
- Elements are located by **markers**, not positions: Word uses content-control tags, Excel uses named ranges (`TF_<Key>`) — moving or restyling never breaks fill or read-back; table rows are cloned from a sample row with fresh ids/ranges.

**Localization**: layout text and headers support i18n keys (`AddParagraphKey` / `AddTableKeys`, …); `BuildInitialTemplateFile(CultureInfo?)` emits per-language templates; runtime messages are bilingual via `CurrentUICulture`. See the [design doc](docs/DESIGN.md) (Chinese).
