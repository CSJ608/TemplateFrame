# 性能快照（Performance Snapshot）

> 环境与日期：2026-08-24 · Windows 开发机 · .NET 8.0 Release · BenchmarkDotNet 0.14（InProcess 短配置：2 预热 + 5 迭代）。
> 数字是**单机端到端实测**（每次迭代完整走一遍打开→处理→保存 OOXML 包），两次采样间波动约 ±20%，
> 用于判断量级与伸缩趋势，不是性能承诺；绝对值随硬件浮动，请以相对比例为准。

基准定义与复现命令见 [test/TemplateFrame.Benchmarks/README.md](../test/TemplateFrame.Benchmarks/README.md)。

## 结论摘要

1. **伸缩性健康**：所有核心路径随行数**线性**伸缩（行数 ×10 → 耗时 ×7~×17，无超线性放大）；
2. **自动映射不是瓶颈**：1 万行双向 `DataPathMapper` 仅 10ms / 2.4ms，占填充总耗时的比例 <7%；
3. **插件对比符合定位**：千行填充 Excel（~60ms）快于 Word（~150ms，SDT 深克隆 + 重发 id 的代价）；回读两者接近；
4. **万行导入导出亚秒级**：Simple 写 / 读 1 万行约 0.3–0.5s，契约路径读约 0.6–0.9s（定义名定位 + 类型转换的功能性成本，约为裸读的 1.8 倍）。

## 解读

- **每行成本**：填充 Word ≈ 150µs/行、Excel ≈ 60µs/行；Simple 读写 ≈ 30–50µs/行——办公单据与列表导入场景（千行）全链路 100ms 级，交互式使用无感；
- **Word 慢在哪**：`FillTableRows` 每行深克隆示例行（含全部 SDT）并重发唯一 `w:id`，这是"用户随便改样式不丢定位"这一核心承诺的成本，2.5 倍于 Excel 属预期内；
- **契约读的溢价**：Simple 契约路径读比裸读多 ~80%，来自每列定义名解析、`ValueType` 转换与行字典构建，是功能成本而非缺陷；
- **内存**：约 6–24 KB/行，有可见的 GC 活动（含 Gen2），仅在极高吞吐的常驻服务场景需要关注；批量文档生成无碍。

## 已知优化候选（当前均不必要，仅备忘）

1. Word `FillTableRow`：每个 SDT 对 `table.Columns` 做一次 `FirstOrDefault`（每行 O(列²)，可预建字典）；
2. Word / Excel `Parse`：逐行遍历后代元素定位列控件（可先按行建 tag 索引）；
3. Simple 契约读：逐格 `FindCell` 在行内线性扫单元格（可按行预建引用索引）。
