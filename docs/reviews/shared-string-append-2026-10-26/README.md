# Excel 共享字符串追加优化（2026-10-26）

范围：普通、契约、模板流式导入共用的磁盘 SST 追加路径。旧 Read/Parse、公开 API、默认限额、字符串缓存容量、临时字节计费、取消及清理规则不变；不做 XML 解析替换、导出 CPU 优化、模板能力扩展或全局并发限流。

## 剖析与候选

基线生产实现为 `797aec9`；`92e23a1` 增加独立探针与 Excel 内部友元访问，不改变读取算法。新增 `shared-profile-read`，在单线程分别测量实际 ZIP 校验、元数据、SST 建库、worksheet 与查询校验，以及额外的顺序磁盘查询、XML-only、append-only 隔离实验。累计分配使用 `GC.GetAllocatedBytesForCurrentThread`，不是峰值内存。隔离实验不可与前四阶段相加当作端到端耗时，亦受前序 JIT 和文件缓存影响。

追加实验包含相同的合成字符串生成。结果定位到可优化的追加开销，不能仅用这些时间差声称测到了某类系统调用次数。XML 每项序列化/SDK 解析仍造成高累计分配，此候选没有解决它，也没有把阶段分配总量误报为峰值工作集。

唯一生产改动：在 `ExcelDiskStrings` 记录成功追加的正文末尾字节位置，索引末尾由 `Count * 12L` 推导；追加时只在当前位置不等于末尾时定位。避免每项读取两个文件 Length、无条件重设 Position。保留读写交错能力，不假定“只能先写后读”；只增加一个 long 字段，不新增缓存、预读或新文件。预算仍在写入前检查，索引 null 标记和 UTF-8 正文不变。

## 独立进程端到端对照

同一六列高基数 shared 输入，输入复制不计时；每个进程独立、无预热、默认 JIT/工作站 GC，系统缓存未清空，机器其他负载不受控。保留基线/候选完整运行文件夹，并通过 `-ProbeAssembly` 明确选择；summary 记录探针、Excel 和 Simple DLL 的 SHA256。基线副本是在候选源码修改前保存，候选只包含上述追加实现变化；探针格式化导致程序集哈希不同，但校验逻辑不变。

| 入口/运行时 | 行数 | 基线秒 | 候选秒 | 轮次 |
| --- | ---: | ---: | ---: | --- |
| 模板 / .NET 10 | 100,000 | 12.118、13.928 | 9.963、9.440 | before → after → after → before |
| 模板 / .NET 8 | 100,000 | 13.051 | 10.866 | before → after |
| 普通 / .NET 10 | 100,000 | 12.301 | 9.095 | before → after |
| 契约 / .NET 10 | 100,000 | 13.861 | 11.772 | before → after |

.NET 10 模板两次均值为 13.023 → 9.702 秒，约降低 25.5%；这是本轮样本观测，不是任意文件的固定提速承诺。其他入口各一组，仅作为方向性补充。worksheet 阶段出现变慢的单次信号也原样保留，不将局部追加实验约 98% 的下降当作整条导入提速。

以上每个端到端 case 均按对应入口逐格校验值、行号和形状；模板还严格验证运行时类型与无诊断。十万行临时内容均为 13,600,084 字节，退出零残留；峰值工作集约 57–59 MiB。

百万行同轮单组对照：107.986 → 81.969 秒，耗时约降低 24.1%。峰值工作集 61.63 → 64.53 MiB（略高，不声称内存下降），临时内容均 136,000,084 字节，零残留。该结果只覆盖本轮六列高基数 shared 样本；不是稳态基准或任意存储介质的提速保证。没有通过增加缓存、绕过预算或减少值校验换取速度。全部 15 个进程 case 成功且未触发保护，原始日志完整保留。

## 验证与结论

候选保留为 `89f016d`。新增 2 场景 × 三框架，在基线和候选均先后通过：5,000 次追加与随机读取交错，覆盖关闭/开启缓存、null、空串、中文及补充平面字符、跨文件缓冲区、反向读取和精确临时字节计费。原 SST 字符数/预算拒绝、缓存边界、非 Seek、取消、消费异常与临时清理测试全部保留。

全方案 Release 构建零警告零错误；net472/net8/net10 共 2,264 测试通过（Core399、Word492、Excel813、Simple560）。已执行方案完整 format；方案及独立探针 whitespace verify、独立探针构建、git diff --check 均通过。归档与 artifacts 原件逐文件比对，除 stdout 尾空行规范化外内容一致。无新增包、项目间依赖、全局状态或代码注释。

本轮只保留这个有正向端到端证据的小改动。后续值得单独验证 SST 单项 XML 序列化/解析的累计分配；需要保持单项 XML 预算、命名空间、富文本与模板 null 语义，不能因发现分配热点就直接换解析器。该候选、导出逐行 CPU、重复工作表扫描均未在本轮实施。
