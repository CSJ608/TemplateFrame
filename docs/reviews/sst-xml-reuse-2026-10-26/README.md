# SST 单项 XML 序列化缓冲复用（2026-10-26）

范围：普通、契约、模板流式读取共用的 SST 扫描。基线 `8bc8f31` 已包含上一轮磁盘追加优化，不能与更早基线混用。本轮仅验证一个候选：每次 SST 扫描复用一个有界文本缓冲和 fragment XmlWriter，每项清空缓冲、序列化、Flush 后仍交给原 SharedStringItem SDK 解析。工作表逐行读取仍用原 fresh writer；富文本拼接和模板直属 Text/null 规则不变，不替换解析器、不新增缓存/公共 API/依赖/全局状态。

## 分配剖析

使用相同 `shared-profile-read` 探针、六列高基数 shared 输入。单线程阶段记录累计分配，不是峰值内存。XML-only 隔离实验仍刻意走原 fresh writer，作为未改路径参照，不能把其数值当作候选 SST 建库的解析成本。阶段及额外隔离实验也不能相加当作端到端耗时。

| 数据行 / SST 项 | SST 建库基线秒 | 候选秒 | 基线累计分配字节 | 候选累计分配字节 |
| --- | ---: | ---: | ---: | ---: |
| 1,000 / 4,006 | 0.135 | 0.162 | 157,705,240 | 92,248,440 |
| 100,000 / 400,006 | 5.130 | 4.176 | 15,795,153,096 | 9,257,975,096 |

十万行 SST 阶段累计分配约减少 41.4%。千行阶段耗时反而增加，不能只凭局部耗时定论。十万行 XML-only 未改路径累计分配 15,779,617,032 / 15,779,442,392 字节，仍然很高，表明本轮没有消除 SDK 对每项 XML 的重新解析。完整阶段日志均保留。

每条路径的顺序是 before→after→after→before；后两次补测与前两次之间穿插其他入口的独立实验。普通基线、契约候选和 .NET 8 候选都出现明显波动。尤其契约与 .NET 8 的首轮总体耗时不能宣称改善，不删除慢结果，也不能在没有证据时直接归因为环境。

补充组支持减少 CPU 工作量的方向，但不抹去先前的混合信号，也不推广为所有入口的固定耗时收益。

百万行模板 .NET 10 同轮 before→after：操作 68.784→57.465 秒（约 -16.5%），整个进程 CPU 67.547→57.063 秒；峰值工作集 62.29→63.80 MiB，略高，不宣称峰值内存下降。两者 4,000,006 项 SST、136,000,084 临时内容字节、退出零残留，均逐格严格验证值/类型/逻辑行号/键数量且无诊断。历史报告的不同轮耗时不能作为这次提速分母。

共 26 个独立进程 case 全部通过且未触发保护。前面十万行端到端 case 临时内容均为 13,600,084 字节，剖析同时保留两份磁盘库所以是两倍；不能把剖析临时量当作公开接口需求。峰值工作集均为整个进程生命周期，不是库独占内存；累计分配下降不等于峰值下降。

## 兼容与预算

- 序列化结果逐字与原 fresh writer 对照：空项/显式空结束标签、中文/补充平面字符、实体与转义、CDATA、注释/PI、直属 Text 与富文本、xml:space、继承/局部命名空间，以及 2,000 次不同命名空间切换。
- 单项预算仍计算实际序列化 XML（含命名空间和转义），恰好限额通过、少一个字符拒绝；连续项各自计费，不把限额误当整 SST 总量。
- 保留每项开始及非空写入的取消检查。初版测试发现 net472 writer.Dispose 会发出零长度写入，取消后触发多余异常；修正为零长度写入不触发检查，预取消仍在 ReadElement 开始检查。相关取消位置、损坏后续项测试三框架回归。
- 每个扫描独立持有并释放 writer，没有全局池；缓冲保留已用容量，受原单项字符限额约束，不累计所有项。共享字符串正文/索引落盘及其预算、缓存、所有权和清理逻辑未改。

## 最终验证与结论

实现与回归提交 `8537ba7`。新增 14 个场景在 net472/net8.0/net10.0 共执行 42 次；全方案 2,306 次测试通过（Core 399、Word 492、Excel 813、Simple 602）。方案与独立 CapacityProbe Release 构建均零警告、零错误；方案格式化及方案/探针 whitespace 验证通过。26 份归档逐项与原始记录核对，summary/stderr/memory 哈希相同，stdout 仅去除末尾空行。

保留此候选：明确的 SST 累计分配下降，以及补充 CPU 和同轮百万行结果支持其价值。但千行剖析、契约和 .NET 8 慢样本仍是适用限制，不将结果表述为所有输入或入口的稳定吞吐保证，也不宣称峰值内存下降。后续 SDK 单项重新解析热点未处理，本轮不扩展到其他候选。仅本地提交，不推送。
