# 模板 Excel 保存与行克隆优化（2026-10-25）

## 结论

保留 `ExcelTemplateFiller.Fill` 的公开接口、输入模型、默认预算和模板处理规则，优化内部克隆与最终打包。6 列、百万数据行在相同 **5 GiB 托管堆预算** 下完成：.NET 10 两次操作耗时 **36.04 / 36.63 秒**，整个进程峰值工作集约 **4.66 GiB**；.NET 8 为 **38.85 秒 / 4.66 GiB**。三次输出均逐格校验通过。

同轮 50 万行对照：旧实现 **30.58 秒 / 3.98 GiB**，最终实现 **18.15 秒 / 2.36 GiB**。这是单次对照观察，不是稳定提速比例或生产 SLA；旧实现仅跑一轮，存在环境/JIT波动。峰值减少约 41% 仅描述本次 50 万行样本。

这不是 SimpleExcel 的低内存流式接口：仍保留输入字典、填充期间的完整工作表 DOM 和最终内存输出流。**不能据此开放 100 个百万行任务同时运行**。不测试 Word 导入，不改变 Word、SimpleExcel 或 Excel 导入路径。

## 实现与兼容性

- `bdc908e`：先给旧实现补充 4 个包保留场景，三个框架全部通过后再优化。
- `fce6171`：关闭工作副本的 XML 自动保存，保留已经加载的部件根元素；SDK 包仍先正常 Dispose，确保新增部件、关系和属性终结。随后直接向新 ZIP 写入已加载 XML，未加载部件按内容复制，工作表逐行写出后释放私有行对象。
- `0d9a5be`：不再先构造全部占位行再逐一覆盖。保存未填充样例的快照，每克隆一行立即填充一行，移除完整克隆列表。样例地址仍在填充前检查，行数/额外单元格/克隆 XML 预算及工作表边界不变。
- `7e9f23c`：容量探针对模板导出增加逐格地址、类型、样式索引和值校验。

所有填充完成后才移除工作副本的行对象，不影响后续契约元素、多个表格或下方元素的定位。克隆源不会被首行填充值和数字格式污染。返回的输出流仍可定位、位置为零，调用方模板流不被关闭；失败时释放内部输出流。没有新增公共 API、配置项或说明性代码注释。

回归覆盖行高/样式、公式原文、下方合并区、页面设置、定义名重指、共享字符串、新图片部件及关系、包属性、外部链接、无关工作表、自定义 XML 注释与不透明二进制部件。另将新打包与 SDK 普通保存的部件 XML 逐个作语义比较，包括命名空间、兼容属性、未知扩展节点、新增工作表和外部关系。比较仅规范化属性顺序与空元素写法，不忽略属性值或节点内容；未加载部件额外比较原始内容字节。非默认及 `%20` 编码的部件名称也覆盖。

ZIP 重新压缩后的字节、XML 属性/命名空间声明顺序、空元素写法不保证与旧输出完全相同。没有测试 Office/WPS 实际打开、排版或打印。百万行容量模板是标准单表样本；复杂模板功能由较小回归样本验证，**不等于所有复杂版式均验证过百万行**。

## 测量口径

基线 `4b3ae07`，机器和版本见 [environment.json](environment.json)：Windows 10、i5-12500H / 16 逻辑处理器、31.8 GiB 内存；SDK 10.0.402，运行时 .NET 10.0.13 / 8.0.32。各 case 新进程、默认分层 JIT、Workstation GC，无预热；模板准备会预热部分共享代码。没有隔离系统负载或清空文件缓存。

探针保持相同保护：5 GiB GC 堆硬上限，采样私有内存超过 6 GiB、系统可用物理内存低于 4 GiB、或 180 秒超时即终止。保护未放宽。日志保留中间候选的 OOM 和系统内存保护终止，不将它们算作最终实现通过。

每六列含四个唯一中文字符串、一个 decimal、一个日期；单表含表头和带边框样例行。数据字典逐任务预先物化，不共享大数据。操作计时包含 Fill 和文件输出复制/关闭，不含准备与校验；新旧模板导出计时口径相同。峰值工作集为整个进程生命周期，包含准备和校验，不是累计分配或库独占内存。GC 硬限制本身会影响性能。

最终 `interleaved-*` case 使用流式 XmlReader 逐格核对输出，避免验证阶段物化百万行；同时核对行/格总数及末行。表头/边框/日期样式索引来自本探针固定生成器，不是通用业务模板校验。早期 baseline/candidate/release-rows case 沿用结构计数和末行检查，不冒充逐格校验。

## 使用边界与后续

最终 Release 构建零警告零错误，net472/net8.0/net10.0 全量 **1,925 次测试通过**（核心 399、Word 492、Excel 621、SimpleExcel 413）；本轮新增 13 个场景共 39 次执行。解决方案和独立探针格式检查通过，汇总见 [validation.json](validation.json)。

大表仍须由业务显式配置有限的 ResourceLimits；默认十万行等安全限额没有提高。只有标题和数据的场景，应优先使用已有 SimpleExcel `WriteStreaming`；需要模板版式的场景继续使用现有 Fill，并为百万行任务保留数 GiB 内存余量，宿主按任务类型排队执行。

本轮没有加入宿主队列、分片导出或新输入 API。进一步把模板填充降低到几十 MiB，需要单独设计真正的流式模板处理及其布局约束，不能由本次结果推导。当前已完成本轮兼容性优化，不继续扩大公开行为或模板能力范围。
