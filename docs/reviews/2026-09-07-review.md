### R1：强类型映射失败未进入诊断结果

- 基线位置：`src/TemplateFrame/Mapping/DataPathMapper.cs:361`；`src/TemplateFrame/Services/TemplateService.cs:115`。
- 条件：TextElement 配置 Key/DataPath，ValueType 使用默认 string；DTO 对应属性为 int；Word 字段内容为 `abc`。
- 结果：`ParseDetailed` 返回 `Qty=0, warnings=0`。引擎字符串解析成功，映射转换失败被宽容模式吞掉，最终只返回引擎告警。
- 风险：无法区分非法输入与真实默认值；同样需要关注表格列、溢出等映射阶段独有失败。
- 验收方向：映射失败携带字段/属性路径、表格行定位、原始值及目标类型进入最终诊断；保留已有引擎告警，避免对同一转换失败机械重复告警；正常数据不新增告警；普通 Parse 的既有严格行为保持。
- 注意：R2 应先修复，R1 必须保持自定义映射语义，不得再次绕开业务重写。自定义映射中无法由框架定位的业务异常不应被伪装成无告警成功。

### R2：详细解析绕过业务映射

- 基线位置：`src/TemplateFrame/Services/TemplateService.cs:124`。
- 条件：契约含 DataPath；业务重写 MapFromData 返回 Qty=999；文件实际 Qty=3。
- 结果：同一文件 `Parse=999, ParseDetailed=3`。详细解析仅根据 DataPath 决定走自动映射，忽略重写。
- 风险：单位转换、字段组合、默认值等业务规则在切换入口时失效。
- 验收方向：ParseDetailed 保留业务 MapFromData 行为；直接重写和通过中间基类继承的重写都有效；MapFromDataDetailed 的显式重写仍可用；默认自动映射的详细解析继续支持宽容行为；不得要求现有业务必须再重写一个方法才能保持结果一致。
- 不预设修复必须使用反射或重构接口；实现者说明兼容性与选择依据，控制公开 API 变化。

### R3：共享 Builder 导致并发状态串扰

- 基线位置：`src/TemplateFrame/Services/TemplateService.cs:55`，包括 Save 和 finally 清空操作。
- 条件：同一服务第一次 BuildInitialTemplateFile 进入 BuildInitialTemplate 后暂停；第二次调用完整结束；恢复第一次调用。
- 结果：第一次调用稳定触发 `NullReferenceException`，因为第二次调用清空共享 Builder。
- 验收方向：同一实例的并发生成不互相覆盖或释放资源；使用事件/同步原语控制测试，禁止依赖 Sleep 碰运气；异常后可继续生成；结果可打开且内容正确。若采用串行锁保护，测试不得制造“首调用等待第二调用完成”的死锁。
- 优先兼容现有无参 BuildInitialTemplate 和 Builder 用法；不得为本项强迫所有消费方迁移。明确串行化或独立上下文的行为与吞吐取舍；不扩大为整库并发重构。

### R4：缓存生命周期

- 基线位置：`src/TemplateFrame/Mapping/DataPathMapper.cs:22`、GetMapping。
- 条件：创建 100 个短生命周期服务，每次 DefineContract 都构造同样内容的新契约和元素集合，调用 ValidateData 触发映射，然后强制 GC。
- 结果：静态缓存计数 `2 → 102`，契约仍被强引用保留。此处元素集合为不同实例，内容相同不意味着 record 键相等。
- 验收方向：不再无限强持有已不用的契约；活跃契约仍能复用映射；保留不同 DTO 类型的隔离与并发正确性；回归正反向、表格和根集合映射。GC 测试应规避 JIT 局部变量存活造成的伪失败。
- 可评估弱关联缓存或有界缓存；说明选型及 netstandard2.0/net462/net8.0 兼容性。不能用“所有服务改成单例”代替库内修复。

### R5：Excel 回读复杂度与性能表述

- 基线位置：`src/TemplateFrame.Excel/ExcelTemplateParser.cs:209,228`；`test/TemplateFrame.Benchmarks/ExcelBenchmarks.cs`；`docs/PERFORMANCE.md`。
- ReadTableRows 每个单元格调用 FindCell；FindCell 从头遍历 SheetData.Elements<Row>() 定位行。R 行、C 列时，行定位部分约 O(C × R²)。

- 验收方向：单次解析建立可复用的查找结构，消除按单元格重复从头扫描工作表；保持稀疏行、缺失单元格、多列对齐、标量与表格并存的行为；补多个行数档位的可复现基准并记录环境、耗时、分配与测量局限。

  - 外层按契约引用身份关联，不使用 record 值相等；契约失去外部强引用后，静态缓存不阻止其及关联类型字典/映射回收。内容相同或 record 相等的不同实例分别缓存，无须改用单例服务。
  - 活跃契约保留其类型字典，同一 DTO 类型复用同一个已发布映射，不同 DTO 类型分别解析属性。使用三个库目标框架现有 API，无新增依赖或公开 API。
  - 两层容器支持并发访问；GetOrAdd 首次竞争可能重复 BuildMapping，但只发布一个构建完成的映射，调用返回获胜条目；发布后映射仅被读取。工厂闭包仅在调用期间使用，不存入缓存；构建失败不缓存异常，后续可重试。数据值、转换结果、输出集合和诊断不进入缓存。

  - 禁止内联的辅助方法创建 100 个同内容但独立的契约，实际执行正反向映射，仅返回契约、元素集合、元素和映射的 400 个 WeakReference；在辅助栈帧退出后执行 GC.Collect / WaitForPendingFinalizers / GC.Collect，避免最后一轮局部变量的 JIT 存活影响断言。

  - DTO 隔离用 int/string 两个不同声明类型执行交叉转换并检查结果及映射身份；契约身份测试使用共享元素列表的 record 副本，明确两个值相等实例拥有不同缓存条目。
