# SST 单项 SDK 成本与兼容性调查（2026-10-26）

结论：SDK 构造加文本选择是当前 SST 路径的主要累计分配来源，但本批不替换生产解析器。只提交对照测试和探针，未新增公共 API、依赖或修改默认预算、磁盘/缓存、取消/所有权/清理规则。生产基线为接续时干净的 `97ae6bb`；调查工具提交 `8b023e5`。历史不同轮耗时不作分母，没有候选端到端提速结论。

## 隔离方式

保留原 `sst-xml-only` fresh writer 控制。新增当前 ElementReader 的纯序列化与序列化后 SDK 构造/直属 Text 选择阶段，顺序 serialize→SDK→SDK→serialize，每次重新打开同一 ZIP 条目；不保存整份 SST，不写磁盘，记录项数和实际序列化字符总量。十万行均为 400,006 项 / 42,400,564 序列化字符。SDK 隔离阶段检查 Text 非 null，完整逐值校验仍在前置 worksheet-and-lookup 阶段。

另用预构造的单个 XML 字符串重复构造 SharedStringItem，比较只构造与构造加选择（构造→取值→取值→构造）。短中文转义文本、两个 run 的富文本各最多 400,006 次；32,767 字符长文本最多 1,000 次。样本 XML 准备在计时外，不累积 DOM；每次新建并保活当前对象。取值优先直属 Text，否则只拼接直属 Run 的首 Text。重复同一 XML 是隔离控制，并不代表业务重复率，也没有增加生产内容缓存。

阶段记录当前线程累计分配，不是峰值内存；不同阶段不可相加当作端到端。进程默认分层 JIT、工作站 GC，阶段顺序会预热代码，文件缓存未清空，外部负载不受控。因此差额用于定位热点，不等于替换解析器后可消除的全部成本或预计收益。

## 兼容性与新发现

新增 25 个场景 × net472/net8/net10：19 个完整 SST SDK 与当前逐项重解析对照、5 个显式选择器规则、1 个已存在差异。覆盖空项/空 Text、首个重复 Text、run 内重复 Text、直属 Text 优先于 run、phonetic、xml:space、转义/实体、CDATA/注释/PI、外来/无命名空间、继承前缀、未知嵌套元素、mc:Ignorable/AlternateContent、长文本及后续项不受污染。这里只是构造 SDK DOM 的对照，不声称全面覆盖 Office/WPS 或所有 SDK MC 处理配置。

发现并单独记录现有语义差异：原始 `<t>a&#13;&#10;b</t>` 经完整 SST SDK 解析为 `a\r\nb`，经 fresh 或 reused 有界序列化再构造 SharedStringItem 为 `a\nb`，三个框架一致。这不是本轮新增回归，也不是复用 writer 独有问题。测试显式保留双方预期，未通过统一换行或忽略差异伪造兼容通过；本轮不悄悄修复行为。

原有 BoundedXmlReuseTests 继续覆盖实际序列化字符预算（含命名空间/转义）、恰好与超限、损坏后续 XML、项间取消、命名空间切换等；全方案回归亦包含公开入口清理/预算测试。零长度写入提前返回未改动。

## 候选决策与后续门槛

热点值得继续研究，但目前证据只证明成本，没有任何替代实现已获兼容性或端到端验证。本批不强行修改生产代码。

- 不采用“拼接所有文本”：违背直属 Text 优先、首值、Run 层级及模板 null 规则。
- 不直接从原始 XML 读取文本并跳过有界序列化：实体换行已有可复现差异，还会改变 MaxRowCharacters 的实际序列化计费，不能称为透明优化。
- 可后续研究严格限定的常见简单项快速路径，保留原有序列化计费和所有非匹配项 SDK 回退。但需先明确支持的结构/命名空间/文本节点类型，候选与当前 fragment SDK 结果及异常逐项对照；长文本、实体换行、未知/重复元素、OOXML 转义文本需继续补样本。保留序列化并不自动保证文本提取与 SDK 相同。
- 原始 SST 与流式路径的换行差异应作为独立兼容性决策处理，不与性能候选捆绑变更。之后若实施候选，再用当时 HEAD 保存基线、相同输入独立进程验证普通/契约/模板；不能将本报告的阶段差额当作候选收益。
